### **0.2. Mot so luu y khi dung TypeScript (LangGraph TS) thay cho Python Langgraph**

1. **Không có** sqlglot.optimizer.qualify**.** TypeScript không có thư viện nào tự bung SELECT \*, gắn tên bảng cho cột và lần theo alias/CTE. UC-09 phải **tự viết** resolveColumns() dựa trên AST của pgsql-parser và cache schema. F7 vì thế tăng khoảng \+2 ngày công. Phương án giữ an toàn:
   - Xử lý đầy đủ các trường hợp phổ biến: FROM bảng \+ alias, JOIN, SELECT \* / t.\*, CTE một tầng.
   - **Gặp cấu trúc chưa phân giải được** (alias mơ hồ, CTE lồng nhiều tầng, LATERAL, hàm trả về bảng) **mà truy vấn chạm bảng có cột nhạy cảm thì chặn** (fail-closed), trả SENSITIVE_COLUMN_DENIED. Ghi vào mục "giới hạn" trong báo cáo.
2. **AST của** pgsql-parser **là JSON thô của Postgres**, ví dụ { SelectStmt: {...} }, { InsertStmt: {...} }, { FuncCall: {...} }. Kiểm tra loại câu lệnh chỉ cần nhìn khoá gốc của từng phần tử trong stmts. Hàm bị cấm được tìm bằng cách duyệt đệ quy mọi node FuncCall và đọc funcname.
3. parse **là bất đồng bộ** (nạp WASM). Server nạp parser một lần lúc khởi động, không nạp theo từng request.
4. **Frontend và backend chung ngôn ngữ.** Có thể chia sẻ type (SQLAnswer, mã lỗi, schema output tool) giữa web và server qua package @shop/contracts.
5. **Script nạp dữ liệu Olist** cũng viết bằng TypeScript (pnpm data:load), dùng csv-parse \+ pg-copy-streams để nạp data nhanh.

### **A.2. Mục tiêu**

Mọi truy cập CSDL của hệ thống chỉ đi qua **một MCP server** duy nhất. Server tự kiểm tra SQL, phân quyền theo scope, che dữ liệu nhạy cảm và ghi audit. Server làm việc này **độc lập với agent**, nên một client bên ngoài cũng không vượt qua được các lớp kiểm soát.

### **A.4. Tiền điều kiện**

- PostgreSQL đang chạy, dữ liệu đã nạp bằng pnpm data:load.
- Role agent_ro đã tạo, chỉ có quyền SELECT.
- Client có token hợp lệ, được khai báo trong policies/mcp_clients.yaml.

### **A.5. Hậu điều kiện**

- **Thành công:** client nhận kết quả đúng schema output. Cột nhạy cảm đã được che theo scope. Có đúng 1 dòng audit cho lời gọi.
- **Thất bại:** client nhận mã lỗi chuẩn, không lộ thông tin hạ tầng. CSDL không thay đổi. Có 1 dòng audit với decision \= denied \| error.

### **A.6. Luồng chính (gọi run_query)**

1. Client gửi request MCP (Streamable HTTP) kèm Authorization: Bearer \<token\> và X-Run-Id.
2. Middleware requireBearerAuth gọi verifier.verifyAccessToken, trả AuthInfo { clientId, scopes, extra.role }.
3. Handler của tool đọc extra.authInfo, kiểm tra run_query cần scope data:read. Client có scope này.
4. SDK kiểm tra tham số theo zod schema.
5. sqlGuard parse SQL bằng pgsql-parser. Câu lệnh đạt các điều kiện: đúng 1 phần tử trong stmts và là SelectStmt (gồm cả WITH/UNION); không có InsertStmt/UpdateStmt/DeleteStmt trong CTE; không có intoClause hay lockingClause; không gọi hàm bị cấm; bảng/cột tồn tại.
6. AccessPolicy.apply:
   - resolveColumns phân giải mọi tham chiếu cột thành bảng.cột.
   - Client thiếu data:sensitive: cột nhạy cảm ở projection bị thay bằng biểu thức che (sửa AST rồi deparse); cột nhạy cảm ở vị trí khác, hoặc trường hợp không phân giải được, thì truy vấn bị chặn.
   - (UC-08, nếu có) Thêm điều kiện lọc dòng.
7. db.ts lấy client từ Pool của agent_ro, chạy BEGIN READ ONLY → SET LOCAL statement_timeout \= '30s' → mở pg-cursor → read(maxRows \+ 1\) → ROLLBACK.
8. Hậu kiểm: quét regex số điện thoại/email trên kết quả, che nếu sót.
9. Ghi audit: client, scope, tool, tham số (literal PII đã che), số dòng, thời gian, quyết định.
10. Trả {columns, rows, rowCount, truncated, maskedColumns, durationMs} dưới dạng structuredContent (và bản text JSON cho client cũ).

### **A.8. Yêu cầu phi chức năng**

- **An toàn:** 3 lớp độc lập, gồm validator, role read-only ở tầng DB, và hậu kiểm PII. Tắt một lớp thì các lớp còn lại vẫn chặn.
- **Không lộ thông tin:** thông báo lỗi và log không chứa DSN, mật khẩu, host, đường dẫn file, stack trace. Bắt buộc dùng pino redact và một hàm sanitizeError() duy nhất.
- **Quan sát:** 100% lời gọi có audit. Audit nối được với trace của agent qua runId.
- **Hiệu năng:** overhead của server (ngoài thời gian DB) ≤ 50 ms/lời gọi. Parser nạp WASM một lần lúc khởi động.
- **Cấu hình:** scope, client và cột nhạy cảm khai báo trong YAML, được kiểm tra bằng zod khi khởi động. Cấu hình sai thì server không chạy.
- **Kiểu dữ liệu:** strict: true trong tsconfig; schema I/O của tool dùng chung qua packages/contracts.

### **A.9. Tiêu chí chấp nhận**

1. Có tài liệu interface: schema input/output của 5 tool và 2 resource.
2. Client chỉ có schema:read gọi run_query thì bị từ chối. Client không có data:sensitive nhận kết quả đã che.
3. Server tự kiểm tra SQL độc lập với agent: client ngoài gửi DDL/DML vẫn bị chặn. Bắt buộc 1 câu lệnh, chỉ SELECT/WITH, có timeout và giới hạn dòng.
4. Mọi lời gọi được ghi vào trace và audit: client, scope, tool, tham số, số dòng, thời gian.
5. Thông báo lỗi không lộ thông tin kết nối.

**Mục tiêu của nhóm:** 100% eval case pass, 0 lệnh cấm được thực thi, 0 rò PII trong output và log.

|          | CTE lồng 2 tầng / LATERAL chạm customers            | Bị chặn (fail-closed)                                   |
|          | Role HR (có data:sensitive) xem salary              | Giá trị thô                                             |
| Chặn SQL | Client ngoài gửi DELETE FROM orders                 | FORBIDDEN_STATEMENT, số dòng bảng không đổi             |
|          | SELECT 1; DROP TABLE orders                         | FORBIDDEN_STATEMENT                                     |
|          | WITH x AS (DELETE … RETURNING \*) SELECT …          | FORBIDDEN_STATEMENT                                     |
|          | SELECT pg_sleep(600)                                | FORBIDDEN_FUNCTION                                      |
|          | SELECT pg_read_file('/etc/passwd')                  | FORBIDDEN_FUNCTION                                      |
|          | Truy vấn hợp lệ nhưng rất chậm                      | TIMEOUT sau 30 s                                        |
|          | **Tắt** sqlGuard (biến môi trường test), gửi DELETE | DB từ chối, mã PG 25006 (chứng minh lớp 2\)             |
| Tham số  | describe_table với table: 123 / thiếu trường        | INVALID_PARAMS                                          |
|          | describe_table("orders; \--")                       | UNKNOWN_TABLE                                           |
| Lộ lỗi   | DB tắt hoặc sai mật khẩu                            | Thông báo không chứa host/user/password                 |
| Audit    | Sau khi chạy toàn suite                             | Mọi request có 1 dòng audit đủ trường, không có PII thô |
