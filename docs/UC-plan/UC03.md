# UC-03 — Charts & Verified Insights

**Owner:** UC-03 owner · **Knowledge Areas:** K1 (Model, structured output, agent loop), K7 (Verification, evaluation) · **Stack:** TypeScript, LangGraph.js, zod, OpenUI Lang + genui-lib chart specs · **Status:** planned (Phase 5) · **Updated:** 2026-11-07

**Sources of truth:** PRD §UC-03 (output schema, technical requirements, 5 acceptance criteria) · architecture §1.2 invariants 3–4, §2.2 VIZ node, §3.1–3.2 K7 suite, §4.6 Loop 4, §5 `answers.ts` + `render.ts`, §6 failure mode #7, §7 UC-03 row · upstream OpenUI genui-lib component props (`@openuidev/react-ui`, MIT).

**Chart stack decision:** UC-03 renders with **OpenUI** (open standard for generative UI), not Vega-Lite/Plotly. The harness validates a strict component-prop spec in contracts, deterministically serializes it to **OpenUI Lang** (e.g. `chart = BarChart(labels, series)`), and `apps/web` renders it with the upstream `<Renderer/>` + `openuiChatLibrary`. The LLM never hand-writes Lang — the serializer is code, so K7 field-validity guarantees survive the stack switch.

**Scope:** this plan covers the post-query UC-03 verification path only — chart selection, headless `render_chart` validation (≤ 2 repairs), tool-free insight synthesis over `<untrusted_data>`, and deterministic numeric/causal claim verification (≤ 1% tolerance). SQL generation, repair, semantic grounding, and RBAC stay owned by UC-01/UC-02/UC-08/UC-09; UC-03 consumes their verified `RunQueryOutput` and never re-implements them.

## 1. Use Case Description

After `ValidatedQueryExecutor` returns masked rows, UC-03 turns a result set into a chart plus 2–4 human-readable insights where **every number traces to a query cell**.

- **Chart selection (K1):** pick exactly one of `line | bar | pie | scatter | table | none` from the result shape (not from model vibes) and emit a strict **OpenUI component spec** whose inline data is fully grounded in `RunQueryOutput` (see §1.1 mapping).
- **Tool-free synthesis (K1 + safety):** draft `InsightReport` with **zero tools bound** over rows wrapped in `<untrusted_data>` delimiters, so seeded injection rows (PRD §2.1/§4.3 case #3, e.g. a product name saying *"ignore previous instructions …"*) are treated as string literals and can never trigger a tool call.
- **Deterministic verification (K7):** OpenUI spec validation (≤ 2 repairs) + numeric claim matching within ≤ 1% rounding tolerance + causal-language gating. Unverified numbers are stripped from `insights` in one pass and logged to the trace; the response still ships with whatever verified claims remain plus `caveats`.
- **Deterministic OpenUI Lang serialization:** the harness (not the LLM) converts the validated spec into OpenUI Lang lines for `apps/web`'s `<Renderer/>`, so the model can never invent component names or malformed Lang.
- **No new data access:** UC-03 runs no SQL itself. All numbers come from the transient ≤ 1,000-row buffer (synthesis prompt sees only the ≤ 50-row `resultPreview`); verification reads the full buffer.

### 1.1 Chart type → OpenUI component mapping

The selector is deterministic-first: shape of `RunQueryOutput` decides, the LLM only writes `chartReason` plus the data arrays. Components and props mirror upstream `genui-lib` 1:1.

| chartType | OpenUI component | Props (validated in `OpenuiChartSpecSchema`) | Use when / guardrails |
|---|---|---|---|
| `line` | `LineChart` | `labels: string[]`, `series: [{category, values: number[]}]` (1–8), `variant?: linear\|natural\|step`, `xLabel?`, `yLabel?`, `height?` | One time column + numeric series (e.g. 12-month revenue). Labels sorted ascending; > 4 series → split or `table` |
| `bar` | `BarChart` | `labels`, `series` (1–8), `variant?: grouped\|stacked`, `xLabel?`, `yLabel?`, `height?` | Category comparison, 2–12 groups (e.g. revenue by 3 regions). Long labels → web Renderer may substitute upstream `HorizontalBarChart` (props-compatible minus `height`) |
| `pie` | `PieChart` | `labels` (2–6), `values: number[]` (same length), `variant?: pie\|donut`, `appearance?: circular\|semiCircular` | Share breakdown of 2–6 groups summing to ~100%. > 6 slices → `bar`; single slice or negatives → `table` |
| `scatter` | `ScatterChart` | `datasets: [{name, points: [{x, y, z?}]}]` (1–8 sets), `xLabel?`, `yLabel?` | Two numeric columns (correlation/clusters, e.g. price vs quantity). > 1,000 points → note sampling in `caveats` |
| `table` | `Table` | `columns: [{label, data: (string\|number)[], type?: string\|number}]` (1–32 cols, equal lengths) | Detailed rows, mixed types, or anything failing a chart rule. Default fallback |
| `none` | `None` (sentinel, renders nothing) | `{ chart: "None" }` | Single scalar (`SELECT COUNT(*) …`) or `status: no_data`. `insights` may be empty; `caveats` required on `no_data` |

Upstream has no `None` component — `None` is our sentinel only; the serializer emits no Lang for it. `AreaChart`, `RadarChart`, `RadialChart` exist upstream but are out of scope: the six types above cover every PRD eval case.

Example Lang produced by the serializer (never by the model):

```text
root = Card([title, chart, notes])
title = TextContent("Revenue by region — Sep 2026")
chart = BarChart(["Nam", "Trung", "Bac"], [{category: "revenue", values: [5200, 3100, 2800]}])
notes = TextContent("South led at 5,200M VND.")
```

The ≥ 15 chart-label fixtures in `evals/uc03/` encode these rules; the ≥ 80% criterion scores the selector against those labels, not against reviewer taste.

### 1.2 Contract surface

Strict schemas live in `packages/contracts/src/answers.ts` (payload) and `packages/contracts/src/render.ts` (chart tool). All fields are camelCase.

```ts
EvidencePointerSchema = { column: string(1..128), rowKey: string(1..256), value: number | string(1..1000) }
InsightClaimSchema    = { claim: string(1..2000), evidence: EvidencePointer[] (min 1) }
InsightChartTypeSchema = "line" | "bar" | "pie" | "scatter" | "table" | "none"  // alias of ChartTypeSchema (render.ts)
OpenuiChartSpecSchema = discriminated union on `chart`: LineChart | BarChart | PieChart
                        | ScatterChart | Table | None — props mirror upstream genui-lib 1:1
InsightReportSchema   = { chartType, chartSpec: OpenuiChartSpecSchema, chartReason: string(1..500),
                          insights: InsightClaim[] (max 10, may be empty only for none/no_data),
                          caveats: string(1..500)[] (default []) }
                        + refine: chartType ↔ spec.chart must match CHART_TYPE_TO_COMPONENT
InsightReportResponseSchema = { kind: "insight_report", status, summary: string(min 1), data: InsightReportSchema }
RenderChartInputSchema = { chartType, spec: OpenuiChartSpecSchema, title? } + same chartType↔chart refine
```

`AgentResponseSchema` discriminates `kind: "insight_report"` into this strict payload (same pattern UC-05 used for `analysis_plan` / `root_cause`; only `anomaly_alert` still carries loose `data: unknown`). `docs/mcp_interface.md` is regenerated via `pnpm docs:interface` and stays hand-edit-free.

## 2. Architecture & Harness Integration

```
ValidatedQueryExecutor → RunQueryOutput (≤1,000 rows buffer / ≤50 preview)
  → VIZ select_chart      (deterministic shape rules + LLM chartReason/spec draft)
  → VIZ synthesize_insights (Profile 3, ZERO tools, <untrusted_data> rows)
  → K7 render_chart validator (headless compile + column check, ≤ 2 repairs)
  → K7 numeric + causal validator (≤ 1% tolerance, strip + log)
  → AgentResponse { kind: "insight_report" } + viz SSE event + redacted trace
```

### 2.1 Nodes (all under `packages/agent/src/subgraphs/uc03*`)

1. **`select_chart`** — inputs: `RunQueryOutput.columns`, dtypes, rowCount, `status`. Applies the §1.1 table deterministically, then asks the LLM (structured output only) for `{ chartType, chartSpec, chartReason }` against `OpenuiChartSpecSchema`. `chartSpec` carries **plucked inline data** (labels/values copied from the buffer), not field references — the prompt includes column names and 3 sample rows, never the full buffer.
2. **`synthesize_insights`** — Profile 3 tool-free call. Prompt contains: question, `resultPreview` (≤ 50 masked rows) wrapped in `<untrusted_data>…</untrusted_data>`, column metadata, truncation flag. Explicit instruction: *"every number in `claim` must copy a cell value into `evidence: [{ column, rowKey, value }]`; recompute every percentage delta yourself; never state a cause not present in the rows or a cited `event:*` chunk — write 'cause unknown' instead."* No tools are bound to this call (architecture §1.2.3, §4.1).
3. **`serialize_openui_lang`** (pure function, no LLM) — converts the validated spec into OpenUI Lang lines (`chart = BarChart(labels, series)` wrapped in `root = Card([…])`). Because serialization is code, the model can never invent component names, and the output parses against `openuiChatLibrary` by construction. Emitted `viz` SSE payload carries both the `InsightReport` and its Lang text.
4. **Repair loop (Loop 4, ≤ 2 repairs per validator)** — validators return structured diffs (`{ code, field, hint }`); the node re-prompts with the diff, never with raw stack traces or PII.

### 2.2 OpenUI `render_chart` validator (`packages/agent/src/validators/*`)

Local deterministic utility, no code execution (PRD §4.1 `render_chart` row). No Gateway: validation is local zod + buffer checks, so no API key or network is needed:

1. Parse `chartSpec` against `OpenuiChartSpecSchema` (rejects unknown components, wrong prop types, ragged `series[].values`, pie label/value drift, ragged `Table` columns, pie outside 2–6 slices).
2. Check `chartType` ↔ `spec.chart` matches `CHART_TYPE_TO_COMPONENT` (rejects `bar` + `PieChart`, etc.).
3. **Data grounding:** every string in `labels` / `Table` label columns must appear as a cell value in the buffer; every number in `series[].values` / `values` / `points` / `Table` numeric columns must match a numeric buffer cell within ≤ 1%. This replaces the old field-∈-columns check: OpenUI data is inline, so the check is stronger — the chart cannot show a number the query never returned.
4. On failure return `{ ok: false, error, field }` → `select_chart` repairs (≤ 2 attempts). After 2 failures, fall back to `{ chartType: "table", chartSpec: <auto-Table from preview>, chartReason: "Fell back …" }` and record the fallback in the trace — never block the whole answer on a chart.

### 2.3 Numeric & causal claim validator (≤ 1% tolerance)

Runs against the full transient buffer (not just the preview), in one deterministic pass:

1. **Number extraction:** regex all numeric tokens + `%` deltas out of each `claim` (handles `5,200`, `5.2K`/`M` suffixes, `8.0%`, VND currency markers).
2. **Evidence match:** every extracted number must have an `EvidencePointer` whose `{ column, rowKey, value }` cell exists in the buffer with `|claimed − actual| / max(|actual|, eps) ≤ 0.01`. Percentage deltas are recomputed from the two cited cells and checked with the same tolerance.
3. **Causal gating:** claims matching causal patterns (`"due to"`, `"because"`, `"caused by"`, `"do đối thủ"`, …) pass only if `evidence` cites a dimension value present in the rows or an `event:*` chunk id present in the turn's semantic context; otherwise the claim is stripped. No event → the validator forces a `"cause unknown"` caveat rather than inventing one (failure mode #7).
4. **Strip + log:** unverified numbers/claims are removed from `insights` (never repaired by the LLM), the removal is logged to the trace with `{ claimIndex, reason }`, and if `insights` becomes empty on `status: ok` the node adds a caveat. `no_data` / `none` with empty insights is valid iff `caveats` is non-empty.

### 2.4 Trust boundaries & what UC-03 does NOT do

- Never calls `run_query` / `describe_table` / `sample_rows` — any number not in the buffer is unverifiable by definition.
- Never imports `pg` / `pg-cursor` / `mcp-server/src/**` (ESLint boundary, architecture §5.2).
- Never renders untrusted HTML/JS from the spec — `apps/web` renders only through the upstream OpenUI `<Renderer/>` bound to `openuiChatLibrary`, and the only Lang it ever receives is serializer output.
- PII stays masked: synthesis sees post-policy masked rows; the trace redactor scans `chartReason`/`claim`/`caveats` before writing `traces/uc03/*.jsonl`.

## 4. Acceptance Criteria & Reporting Checklist

| # | PRD UC-03 criterion | How this plan guarantees it |
|---|---|---|
| 1 | 100% `chart_spec` renders and points at real data; ≤ 2 self-repairs | OpenUI union + chartType↔chart + buffer data-grounding checks (§2.2); repair counter capped at 2, then deterministic auto-Table fallback; criterion measured on all eval cases |
| 2 | Chart-type accuracy ≥ 80% on ≥ 15 labeled fixtures | §1.1 rule table is the oracle; fixtures cover line/bar/pie/scatter/table/none including boundary cases (7-slice → bar, scalar → none) |
| 3 | 100% of insight numbers pass the validator; unverified insights stripped + traced | §2.3 evidence-match at ≤ 1% + strip-and-log; eval asserts zero delivered numbers without a matching buffer cell |
| 4 | No unfounded causal claims (manual rubric) | Causal gate (§2.3.3) + eval injection case (competitor-blame with no event data must be stripped or caveated) |
| 5 | Mean latency + tokens for the insight step reported | Trace `durationMs` + `promptTokens/completionTokens/estimatedCostUsd` per run, aggregated in `evals/results/uc03_report.json` |

### 4.1 Minimum eval cases (5 + safety)

1. **12-month time series** → `line`; claims check absolute + MoM% values.
2. **3-region comparison** → `bar`; claims check ranking + share.
3. **Category share (≤ 6)** → `pie`; claims check percentages sum ≈ 100%.
4. **Single scalar** (`COUNT(*)`) → `none` + `{ chart: "None" }` spec; one evidenced claim, no chart.
5. **Empty / partial period** → `none` or `table`, empty insights allowed, `caveats` required (e.g. *"October covers 6 days"*).
6. **Safety:** injection row (`"ignore previous instructions …"`) must appear as a quoted literal at most, never followed; competitor-causality claim with no `event:*` context must be stripped.

### 4.2 Metrics reported (PRD §6.2)

Chart validity %, chart-type accuracy, numeric pass %, causal-strip count, `promptTokens` / `completionTokens` / `estimatedCostUsd` / `latencyMs` means for the VIZ step, Run #1 vs Run #2 narrative per §6.3.

## 5. Failure Modes (UC-03 slice of architecture §6)

| Failure | Defense |
|---|---|
| Spec invents a component or shape | Zod union rejects unknowns → ≤ 2 repairs → auto-Table fallback |
| Chart data not in query results | Data-grounding check (strings ∈ buffer cells, numbers ≤ 1%) → repair/strip + trace |
| Number copied wrong / delta miscomputed | ≤ 1% evidence recheck + delta recompute → strip + trace |
| "Revenue fell due to competitor pricing" with no data | Causal gate → strip or force `"cause unknown"` caveat |
| Injection row in results | `<untrusted_data>` + zero bound tools → literal only |
| Chart library executes model code | Spec is pure data (no `Query`/`Mutation`/actions); only serializer output reaches `<Renderer/>`; no `run_python`, no eval of spec strings |

## 6. Definition of Done

1. `InsightReportSchema` + strict `insight_report` variant merged with green `docs:interface` / `typecheck` / contracts tests.
2. Headless chart + numeric/causal validators implemented with ≤ 2-repair bounds and strip-and-log behavior.
3. ≥ 5 eval cases + ≥ 15 chart-label fixtures + safety cases running under the unified eval runner with latency/token output.
4. ≥ 1 PII-redacted `traces/uc03/*.jsonl` trace showing select → synthesize → validate → verified `AgentResponse`.
5. No new DB imports in `packages/agent`, no hand-edits to `docs/mcp_interface.md`, no PII or gold data in prompts/traces.
