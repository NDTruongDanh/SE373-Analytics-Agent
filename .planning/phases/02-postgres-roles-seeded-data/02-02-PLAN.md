<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub raw URLs → data/.cache/ | Untrusted bytes enter here; SHA table is the checkpoint |
| seeds.json (UC-owner edited) → loader | Owner-controlled data becomes database rows |
| seeded docs → OpenWiki/agent | Hidden knowledge must not cross into retrievable docs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-2-05 | Tampering | download.ts supply chain (mirror MITM or mutated CSV) | high | mitigate | HTTPS plus pinned blob-SHA verification before parse; fail-closed mismatch error names the file; no Kaggle credential flow means no token to steal |
| T-2-06 | Tampering | seeds.json abuse (malicious reference_sql or extreme magnitudes) | low | accept | zod strict validation bounds shape and sizes; seeds only affect the local dev database which ships no access control decisions; rationale: loader never executes reference_sql, verify only reads it |
| T-2-07 | Disclosure | faker PII colliding with a real person | low | accept | Synthetic-only generation documented in README per DATA-07; faker output carries no real personal data by construction; rationale: collision probability is negligible and the data is labeled synthetic everywhere |
| T-2-SC | Tampering | npm/pip/cargo installs | high | mitigate | No installs in this plan; inherits the Task-2-of-02-01 postinstall audit and human-approval gate for the four new specifiers |
</threat_model>
